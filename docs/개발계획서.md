# 루틴 체크 앱 개발 계획서 (v1)

## 1. 개발 방향
- 1차 목표는 Android 앱이다.
- 백엔드 서버 없이 로컬 저장만으로 동작해야 한다.
- 웹은 당장 고려하지 않고, 추후 필요 시 데이터 import/export로 확장 가능성을 남긴다.

## 2. 기술 선택 제안

## 2.1 권장 스택
- 앱 프레임워크: `Expo + React Native + TypeScript`
- 라우팅: `Expo Router` 또는 `React Navigation`
- 로컬 저장소: `SQLite` (`expo-sqlite`)
- 알림: `expo-notifications`
- 상태 관리: React 기본 상태 + 필요 시 `Zustand`
- 배포 형태: Android APK/AAB

## 2.2 Electron 사용 판단
- 결론: 현재는 `Electron`을 쓰지 않는 것이 맞다.
- 이유
  - `Electron`은 데스크톱 앱용이다.
  - 현재 목표는 Android 앱 기능, 특히 로컬 알림이다.
  - `Electron`을 써도 Android 앱 문제는 해결되지 않는다.
  - 앱 기능 중심이면 `Expo/React Native`가 더 직접적이다.

## 2.3 알림 기능 방향
- 1차부터 로컬 알림을 앱 기능으로 구현한다.
- 기본 지연 알림뿐 아니라, 해제 전까지 반복되는 리마인드 알림을 지원한다.
- Android 12+에서는 정확한 시각 알림을 위해 exact alarm 권한 검토가 필요하다.

## 3. 핵심 기술 판단

## 3.1 왜 Expo 기반이 맞는가
- React Native 앱을 빠르게 시작할 수 있다.
- Android 실기기 테스트 흐름이 단순하다.
- `expo-notifications`, `expo-sqlite` 같은 필수 기능을 바로 붙이기 쉽다.

## 3.2 왜 SQLite가 맞는가
- 앱 로컬 데이터 구조를 안정적으로 저장할 수 있다.
- `Task`, `TaskLog`, `ReminderRule`, `ReminderEvent` 같은 관계형 구조에 적합하다.
- 향후 export/import 시 전체 데이터 스냅샷을 만들기 쉽다.

## 3.3 알림 관련 현실적인 판단
- "N시간 후 1차 알림 + 해제 전까지 반복 알림"은 앱 기능으로 구현하는 것이 맞다.
- 반복 알림은 일반화된 기능으로 설계해야 한다.
- 예: 출근 후 9시간 뒤 알림, 미해제 시 1분 간격 반복, 퇴근 체크 또는 수동 해제로 종료

## 6. 지금 결정이 필요한 항목

## 결정 1. 알림 정확도 목표
- 질문: "앱이 꺼져 있어도 몇 시간 후 정확히 알림"이 필수인가?
- 현재 방향: 필수로 간주하고 앱 기능 중심으로 설계

## 결정 2. 저장 범위
- 질문: 완전 로컬만 사용할지, 나중에 동기화할 가능성이 있는지
- 현재 추천: 로컬 전용으로 시작, export/import만 지원

## 결정 3. 체크 상태 정책
- 질문: `SKIPPED`를 완료율 분모에 포함할지
- 현재 추천: 포함

## 결정 4. 과거 수정 허용 범위
- 질문: 과거 날짜 체크를 어디까지 허용할지
- 현재 추천: 수동 수정 허용, 대량 수정 미지원

## 결정 5. 카테고리 정책
- 질문: 카테고리를 고정값으로 둘지 사용자 정의로 열지
- 현재 추천: 고정값으로 시작

## 결정 6. 반복 리마인드 종료 정책
- 확정
  - 사용자가 수동 해제 시 종료
- 추가 정책
  - 수동 해제 시 `dismissed_at` 기록
  - 알림 기준은 관련 테스크의 종료 시각(`ended_at`)
  - 최대 반복 시간은 추후 옵션으로 확장, MVP에서는 필수 아님

## 결정 7. 반복 간격 기본값
- 확정
  - 기본값: `1분`
  - 최소값: `1분`
  - 사용자 조정 가능

## 8. 현재 추천 결론
- 지금은 `Electron` 대신 Android 앱으로 간다.
- 스택은 `Expo + React Native + TypeScript + expo-sqlite + expo-notifications`가 적절하다.
- 반복 리마인드 알림은 특정 출퇴근 시나리오가 아니라 일반 규칙 엔진으로 설계한다.
